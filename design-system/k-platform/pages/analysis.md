# 信息提取

继承 ../MASTER.md 与 workspace.md。本页定义 V2 分析在工作台中的差异规则。

## 定位

信息提取是工作台中的一个工作模式：仍以团队、知识库为范围，左侧保留资料清单，
右侧从问答切换为“分析”。分析结果**仅创建者本人可见**，团队共享资料不等于共享分析。
页面顶部持续显示当前团队/知识库与“仅本人可见”，不做整页跳转，避免丢失资料上下文。

## 布局

```text
┌──────────┬────────────────────────────────────────────┐
│ 团队导航 │ 当前团队 / 知识库        团队共享            │
│          ├────────────────────────────────────────────┤
│          │ 文档与问答   [问答 | 分析]   知识库选择器     │
│          ├─────────────┬──────────────────────────────┤
│          │ 资料清单    │ 新建提取 / 历史记录           │
│          │             │ 文档选择、字段定义            │
│          │             ├──────────────────────────────┤
│          │             │ 进度、信息表、依据摘录        │
└──────────┴─────────────┴──────────────────────────────┘
```

- 桌面沿用 `workspace__panels` 两栏：资料栏 260–360px，分析占剩余空间。
- 分析内部只在需要时再分栏（历史列表 + 详情），宽度不足时改为上下堆叠。
- 结果表在自身容器内横向滚动，长中文换行，不能撑宽整个页面。
- 640px 以下与工作台一致改为纵向排列，资料清单可滚动。

## 状态与文案

字段状态：已提取、未提及、待核实、处理失败。逐文档状态：排队、处理中、成功、失败。
任务状态：排队、处理中、已完成、部分完成、失败、来源已失效。状态同时用文字表达，
不能只靠颜色。

- 尚未选择可用文档：说明先上传并等待处理完成，提交按钮禁用。
- 提交失败：保留已填字段与文档选择，显示服务端文案与下一步。
- 重复点击提交：复用同一提交标识，成功后才允许生成新任务。
- 处理中：显示已处理文档数/总数与阶段，不显示伪百分比或预计时间。
- 未提及：明确“全文已处理，未找到该字段”，区别于失败与待核实。
- 待核实：显示保留的原文与歧义说明；不替用户挑选一个取值。
- 来源失效：只显示任务元数据、范围与原因，隐藏字段值、摘录和结论。
- 历史：仅本人记录，显示标题、状态、文档数与时间；刷新后恢复。

## 依据

每条已提取字段默认展开依据，包含资料标题、位置与原文摘录。依据折叠可用键盘操作。
来源删除后不展示旧摘录。

## 批量与对比

- “信息提取”支持勾选多份资料；每份资料独立执行，部分失败时任务为“部分完成”，
  成功资料的结果照常展示，失败资料不显示半成品。
- “文档对比”要求至少两份资料，先逐文档提取指定字段，再生成对比表。
- 对比结论只取“共同点 / 差异 / 待核实”三类。每个结论列出参与资料，并可展开查看
  属于这些资料的原文依据；未提及不构成与有值文档的冲突。
- “重新运行”预填原任务的类型、标题、资料范围与字段定义，并记录来源任务；用户改动
  任一表单项后按新建分析处理。旧任务与旧结果保持不变。

## 来源标识

结果顶部显示状态与来源。分析记录带 `provider` / `model`；当全部结果来自
`provider=stub` 时，必须显示“当前结果来自验证用固定规则替身，只用于检查流程和依据
结构；不代表真实模型的提取或对比质量”。该提示不能省略，也不能改写成质量结论。

## 交互

- 范围切换或组件卸载时停止旧轮询；迟到的响应不能覆盖新范围的数据。
- 表单支持键盘操作与可见焦点；类型选择用原生控件，提供可理解的中文标签。
- 不在结果区域加入报告、导出或业务裁决入口；V3 再设计。
