# 知识工作台设计规范

适用于 V1–V5 的登录、邀请、知识工作台与管理入口。规范反映当前产品，旧截图仅供布局参考。

## 读取与执行

修改页面、组件、交互或样式前，先读本文件，再检查 `pages/<页面名>.md`。页面规范仅覆盖该页面的差异；公共规则以本文件为准。视觉变量以 `frontend/src/styles/tokens.css` 为代码来源，公共控件在 `global.css`，页面布局在 `app.css`。

新增界面按“定位 → 布局 → 状态 → 实现 → 浏览器核验”执行。复用现有语义变量和组件；确需新变量时先说明其角色，再同时更新规范及代码。产品规则以根目录 V1–V5 范围为准，当前权限以 `V5-SCOPE.md` 为准，技术约束见 `docs/architecture/README.md`；本规范不批准新业务能力。

## 定位与视觉主张

产品是团队共同使用的文档与知识工作台。主要任务是组织文档、提问、分析、核对原文、沉淀笔记及审阅报告，并支持后台自动成稿。界面采用“文档阅览台”：稳定的团队边界、可阅读的工作区、可核对的依据。

视觉记忆点是青绿色的引用关联：正文使用小号上标，右侧抽屉展示来源、位置与摘录，悬浮或聚焦引用时高亮回答对应句段。引用默认收起，阅读与原文核对各占清晰位置。

## 配色

| 角色 | 颜色 | 用途 |
| --- | --- | --- |
| 石板蓝 | `#233B4A` | 团队导航、登录说明区 |
| 冷白 | `#F3F6F8` | 工作台底色 |
| 阅读白 | `#FFFFFF` | 资料与问答阅读面 |
| 墨蓝 | `#243746` | 正文、标题 |
| 青绿 | `#176B65` | 主要行动、焦点、依据、可检索状态 |
| 辅助灰 | `#60717D` | 解释、位置、元信息 |

引用底色、分隔线、危险色等辅助变量在 tokens.css 中定义。布局分隔线用于分区，输入边界使用更深的 control-line。普通文字对比度至少 4.5:1；控件边界和有意义的图形至少 3:1。状态同时有文字，避免仅靠颜色传达。

每个局部任务有一个明确主行动：登录、上传或发送。删除采用弱化的危险操作，保留可访问名称与确认。选中导航通过背景、边界与 aria-current 共同表示。

## 字体与密度

- 中文优先：PingFang SC → Noto Sans CJK SC → Microsoft YaHei → system-ui。不依赖远程字体，避免外网字体阻塞和中西文风格割裂。
- 正文与标题同一字体家族。回答正文 14px / 1.95；常用界面文字 13–14px；辅助文字下限 12px；页面标题 24–28px；登录说明标题 30–44px。
- 标题字重 600，正文 400，文件名 500。正文左对齐，答案最大宽度 72ch；居中仅用于登录入口和空状态。
- 间距采用 4px 基础节奏，常用 8 / 12 / 16 / 20 / 24 / 32。控件圆角 6px，工作区容器 10px；引用条左侧直角表达依据边界。
- 普通按钮高度至少 42px；窄屏主要操作和独立图标按钮至少 44px。可见焦点外圈 3px，不能被容器截断。

## 信息架构

业务界面采用首页与知识库两层；管理入口见 `pages/management.md`，沿用公共配色、控件与字体。

- 首页：知识库入口为主体，团队列表为辅助；知识库卡片只呈现名称、所属团队与进入动作。
  提供搜索、团队筛选；已加入团队者均可建库，维护入口按知识库有效权限，团队管理按团队角色。
- 知识库内部：顶部左侧返回首页、知识库名称下拉切换、所属团队；右侧登录者菜单。
  左侧为可展开的资料目录，右侧切换问答、分析、自动成稿、笔记、报告；不再占用整列展示团队导航。
- 引用抽屉：默认不展示，点击正文上标或回答下方唯一“查看引用”按钮打开。
  桌面并排压缩阅读区，保持正文可对照；窄屏覆盖显示，关闭后返回触发位置。

```text
首页：知识库（搜索 / 团队筛选 / 新建） | 团队（团队设置）
知识库：返回首页 / 切库 / 团队 / 可见范围 / 有效权限 / 个人菜单
        资料目录 | 问答、分析、自动成稿、笔记、报告 | 依据抽屉（按需）
平台管理：独立入口，负责账号与团队元数据
```

页面内容左对齐，答案保持阅读宽度。采用现有石板蓝/阅读白/青绿配色和 PingFang 系统字体，
不引入远程字体、装饰动效或新的品牌变量。视觉强调仅用于当前知识库、工作模式和证据关联。
桌面高度跟随视口，目录、回答、分析与引用抽屉各自滚动，输入区保留在可见范围。
760px 及以下资料目录通过“资料”按钮打开，引用抽屉覆盖工作区；被覆盖的正文不可聚焦。

## 交互与文案

- 按真实任务命名：“上传资料”“新建知识库”“发送”“退出登录”。领域名“团队”“知识库”保持一致。
- 当前范围始终可见；切换团队或知识库时清空该工作区的临时问答、文件筛选及输入，避免上下文混淆。
- 加载、空内容、处理中、成功、失败、禁用都须有具体呈现。解析失败保留原因；上传部分失败后刷新已成功的资料。
- 初始无资料时引导上传；有资料时建议问题只填入输入框，由用户发送。问答无依据时说明需补充资料或调整问题。
- 输入允许粘贴、密码管理器与浏览器自动填充。提问支持多行及 Cmd/Ctrl + Enter；中文输入法组合过程中不触发发送。
- 异步失败保留问题或表单内容，提示下一步；删除需确认对象与后果。
- 图标统一使用 `Icon.tsx` 与 `FileTypeIcon.tsx` 的 Tabler Icons 线条图标，公共图标默认 20px、1.7px 描边。装饰图标 aria-hidden，独立图标按钮有名称。新增图标沿用这套几何语言。
- 不用装饰性动画。反馈色过渡 160ms，尊重 prefers-reduced-motion。当前只实现浅色阅读界面；深色导航不是深色主题。

## 完成标准

每次视觉修改后：

1. 前端检查与生产构建通过；记录既存警告。
2. 浏览器检查桌面、窄屏与横屏，无横向溢出，关键操作可达。
3. 用真实或独立测试数据检查空状态、处理中、失败、引用、知识库及团队切换；截图不能伪装为真实模型质量验证。
4. 键盘可访问资料目录、上传、切换、发送、引用上标和抽屉；Escape 关闭抽屉并恢复焦点；密码允许粘贴。
5. 检查实际配色对比度、长中文文件名及长回答换行、减少动态效果规则。
6. 设计变更同步更新相关规范和预览；不要只增加覆盖样式而保留相互矛盾的旧规则。

## 视觉基线与证据

`previews/` 保留早期独立示例截图，供层级、密度与响应式参考，不能代表当前全部功能或真实模型质量；冲突时以当前页面规范和代码为准。

既有截图检查覆盖 1440×900、1024×768、768×1024、375×812、812×375 与短屏；配色基线曾测正文对白色 12.28:1、辅助灰对白色 5.05:1/底色 4.66:1、主按钮白字 6.31:1。当前改动仍需按完成标准重新核验。工程与浏览器实际结果统一见 `docs/implementation/README.md`，不在各页面重复累计测试数量。
