2. 读 README 与相关配置决定命令。测试只使用独立数据库；不清空实际团队资料，不读取或打印真实凭据。
3. 先列本切片输入、输出、状态及必要测试，再实现；发现供应商、权限或部署变化时将具体取舍交用户，其余常规工程细化直接完成并记录。

## T01：合同、样例与预算

**目标**：开发者能用固定请求和预期结果判断后续实现正确与否。

交付：

- 在 `evaluation/v2/` 建立最小公开样例及来源说明，至少包括正常提取、未提及、多候选、条件不同的相似条款、文末依据、重复片段和文档内指令。四种格式均有解析定位样本；保留预期字段和原文位置。
- 固定字段定义、结果/任务状态、创建/详情/依据的最小 schema；根据实施指导写成功和失败示例。建立 V2 的最小 OpenAPI 类型生成入口，前端复用现有请求封装；未实现路由的 schema 用显式导出，先不暴露空实现接口。
- 在现有配置体系增加保守的分析限制初值：文档数、字段数、单文档及总文本量、调用输入/输出预算、累计调用数、任务时间、自动重试与用户/团队活动任务数。记录选择依据及超限行为；所有值可配置。
- 编写 schema/边界验证：重复字段、错误类型、超限、非法输出/引用等；纯协议测试无需模型和业务数据库。

**完成标准**：样例可校验；V2 类型生成可重复、与后端 schema 一致；每个输入限制有明确服务端错误；配置值及临时取值理由写入本项完成记录。实际容量未经测试不得标记已验证。暂不建设完整评测平台或全量数据库结构。

## T02：单文档后台闭环

**目标**：提交一份可用文档和字段定义，后台用确定性替身完成分析，刷新后本人仍能读取。

交付：

- 分析任务、逐文档执行、结果与依据的最小迁移，团队/知识库/本人复合归属及 RLS；幂等提交与入队原子化。先只开放单文档提取，批量请求明确拒绝。
- 接入现有 worker，增加分析专用领取/续租/回收路径；原文解析任务继续工作。创建、分页列表、详情及依据读取使用真实权限检查。
- 来源快照、发布前校验和读取时实时失效视图从本项具备；成员移除后不能继续发布。初版替身也必须走完整租约和持久化链路。
- 同步 API schema、错误及前端类型；将测试数据清理覆盖新增表，防止测试之间残留分析记录。

**验证**：真实独立 PostgreSQL 的创建→领取→完成→读取；同键重复返回原任务，不同请求冲突；跨团队、跨知识库、同团队其他用户及管理员访问拒绝；连接池上下文复用；创建后来源删除及成员移除；过期令牌不能发布。

**完成标准**：重启 worker 后已保存任务继续执行；API/worker 使用受限角色通过上述测试。只声称替身流程通过，不声称真实提取质量通过。

## T03：完整覆盖与真实提取

**目标**：字段依据位于文档任何已发布位置时均有处理机会，字段值和引用接受服务端校验。

交付：

- 全片段有界分批、超长片段切分、覆盖计数、候选合并去重及文本指纹校验；中间结果与最终字段隔离。
- 小型分析适配接口及同供应商真实实现，复用现有凭据来源；文本/数字/日期/文本列表输出校验。字段状态及单位/精度规则按范围执行。
- 临时错误和输出非法的有限重试、预算计数、脱敏错误与用量记录；模型不可用时明确失败。只有显式测试配置使用替身，真实验收缺少凭据时不能自动降级后报成功。
- 值和依据一同发布；校验陌生字段、其他文档片段、伪造位置与非原文摘录。语义是否支持通过样例和后续人工评测判断。

**验证**：依据在最后片段；同字段分布在不同片段；重叠内容去重；一批失败不会判未提及；单位不明、年份不完整、同字段冲突；非法 JSON、类型错误、越界引用和文档指令；达到调用上限后明确结束。

**完成标准**：确定性测试覆盖上述边界；有真实凭据时单独跑少量公开样例并记录结果，无凭据则明确真实接入未验证。不得用小样例宣布 T08 质量验收完成。

## T04：单文档用户界面

**目标**：用户能在现有工作台完成单文档提取，离开后返回可继续核对结果。

交付：

- 先读设计 MASTER 和 workspace 页面规范，补充 `design-system/k-platform/pages/analysis.md`，再实现分析入口、字段表单、本人历史、轮询进度、结果和依据核对。
- 显示当前团队/知识库及“仅本人可见”；不可用文档不能提交；等待、失败、未提及、待核实与来源失效各有文案。
- 创建错误保留表单；重复点击复用本次提交标识，明确成功后才清理。范围切换及组件卸载停止旧轮询，迟到响应不能覆盖新范围。
- 使用现有 tokens、图标和请求错误处理。结果允许区域内横向滚动、长中文换行，界面不增加正式报告或导出入口。

**验证**：前端检查及构建；浏览器按设计规范检查 1440/1024/768/375px、短屏及键盘；用独立示例数据覆盖空态、处理中、失败、引用、来源删除、刷新恢复与范围切换。

**完成标准**：截图/浏览器记录能证明流程及布局；明确示例数据与真实模型验证的区别。V1 上传、问答、会话和成员操作仍可用。

## T05：批量提取与部分成功

**目标**：选择多份文档后逐份处理，失败不覆盖成功结果，用户能看到准确覆盖范围。

交付：

- 将 T02 单文档限制扩展至配置上限，原子固定文档清单；混入无权限、跨库或不可用文档整次拒绝。多选、字段定义、信息表和计数同步落地前后端。
- 按文档保存检查点，失败只自动重试未成功文档；父任务 completed/partial/failed 的计算与收敛。成功文档的字段均完整发布，不展示失败文档的半成品。
- 在已有执行链路落实用户/团队活动任务并发限制，原子占用与释放；worker 对解析与分析公平调度。
- “重新运行”预填已有配置并创建新任务、记录来源任务；整批重新执行，旧结果不覆盖。含失效来源时先让用户调整选择。

**验证**：三文档两成功一失败、全部失败、未提及仍算成功；输入顺序与并发完成顺序不同；重复提交；失败重试不重复处理成功文档；重新运行保留旧记录；并发创建到达上限及终态释放；同一用户属于两个团队不串结果。

**完成标准**：批量创建到结果表/依据核对闭环通过；数量、状态和错误与实际处理一致；单文档回归通过。

## T06：多文档对比

**目标**：至少两份文档按明确维度形成对比表及有依据的结论。

交付：

- 对比类型复用逐文档提取，增加汇总阶段的有界输入、租约、持久状态和输出校验；模型、提示词与 schema 版本可追溯。
- 结论区分共同点、差异和待核实项，列出参与文档及依据；按实施指导处理缺失、不同条件和部分失败。
- 前端提供类型选择、维度填写、对比表、结论依据与重新运行；不得提供制度效力、合规判决等业务结论功能。

**验证**：相同条件不同值；不同适用对象或时间；一份未提及；一份失败不生成全局结论；全部提取成功但汇总失败为 partial；模型编造参与文档/字段被拒绝；汇总超预算不静默丢项；汇总阶段来源删除不得发布。

**完成标准**：指定维度逐项可核对，结论的参与范围准确，未比较维度不宣称全部一致。信息提取模式回归通过。

## T07：综合故障与隔离

**目标**：故障、撤权及竞争不会导致结果泄漏、重复发布或永久处理中。

交付与必要测试：

- 两个 worker 同抢文档/汇总执行、过期执行者迟到、续租失败、最终尝试崩溃、子任务终态但父任务未收敛、汇总重启恢复；全部最终到达确定状态。
- 删除与提取发布、删除与汇总发布、删除与结果/引用读取、重索引与快照核对；校验响应正文无字段/摘录/结论残留，后台清理失败也不恢复展示。
- 同团队他人、管理员、跨团队成员猜任务及依据 ID；连接池复用、worker 上下文恢复、成员移除前后；受限角色和函数的实际权限验证。
- 并发提交限额、预算耗尽、超时、重试退避与公平调度；记录不会重复释放额度或无上限调用模型。
- 检查日志、缓存及列表响应，不能包含私人提取内容、原文或凭据；修复本轮发现的问题并补对应回归。

**完成标准**：故障测试以确定性时序/屏障证明竞争条件，不能只用顺序调用或随机等待替代。权限/删除泄漏为阻断项，不接受“前端隐藏即可”。

## T08：公开资料真实验收

**目标**：量化值正确、遗漏、引用及对比质量，并得到实际容量和耗时数据。

交付：

- 扩充 T01 语料到 V2-SCOPE 建议规模；真实公开资料覆盖四种支持格式、长文、条件歧义、列表、缺失和不可信指令。预先固定字段/维度、预期值、原文位置及差异。
- 在 `evaluation/v2/` 增加运行、记录和评分入口，按实施指导分别计算指标。真实生成结果与人工判定分开保存，独立评测团队/知识库与凭据使用遵守现有规则。
- 对固定小批量和配置上限批量测排队/执行耗时、p50/p95、失败、用量及并发对 V1 问答/上传的影响；超时和异常计入结果。
- 检查问题归因；仅对已证明的覆盖、提示词、合并或校验缺陷做必要改进，再用固定集回归，不能通过删难题或无限重试提高指标。

**完成标准**：在 `docs/operations/V2-QUALITY-ACCEPTANCE.md` 记录实测证据及人工结果。人工评审未完成或量化门槛未由用户确认时，明确写“评测已执行，正式质量验收未完成”；工程完成和正式验收分别记录。
