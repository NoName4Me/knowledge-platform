## T01：确认要求与执行记录

**目标**：服务端保存用户确认的固定计划，创建当前知识库内仅本人可读的执行记录。

- 输入复用现有字段/维度与报告要求，固定显式文档集合、来源快照、分析方式和要求。首批执行计划由固定模板生成，模型建议须经过现有结构校验与用户确认。
- 定义最小 API 合同、归属、阶段、终态与错误；区分排队、处理、完成、失败、取消及来源失效。阶段成功与报告人工复核状态分开，不把需求建议阶段作为已授权的后台执行。
- 保存提交幂等键与请求指纹；同键同输入返回原记录，同键不同输入冲突。服务端原子限制用户/团队活动执行数，同时遵守 V2 子任务限额，结束只释放一次额度。
- 建立执行、步骤、成果关联和必要事件的最小存储及 RLS；团队、知识库和创建者关联一致。调度只领取必要身份元数据，逐事务恢复团队与用户上下文。
- 同时写入确认启动事件。未接入 T02 前，协调入口应明确不可用，不接受会永久排队的生产任务；替身闭环在测试中验证保存与状态收敛。

**验证与完成标准**：独立 PostgreSQL 验证创建、刷新读取、同键重放和冲突、超额并发拒绝，以及跨团队、同团队他人和管理员越权拒绝；范围外、不可用或重复文档被拒绝，事件无正文或密钥。接口合同与迁移可检查，记录剩余依赖。

## T02：自动衔接分析与报告

**目标**：无需用户再次操作，执行器完成“创建分析 → 等待分析 → 创建报告草稿”，结果持久且不会重复。

- 工具采用固定允许列表和类型化输入，复用 `analysis.py`、`analysis_tasks.py`、`knowledge_products.py` 的业务能力；业务服务调用不绕过归属、权限和来源校验。
- 为每次执行创建独占子分析，原子保存关联或可恢复的幂等标识；等待阶段只保存状态并归还调度。子分析完整成功才能进入报告步骤，部分成功与失败停在明确错误状态并保留中间成果入口。
- 报告步骤复用 `create_report_from_analysis`；报告与步骤成果关联在同一事务幂等提交。崩溃重领先查已提交成果，旧租约不能新增报告或覆盖关联。
- 为新增协调步骤落实租约、续租、过期回收、有界重试和最后一次崩溃收敛。解析、分析和协调步骤公平调度，模型调用在事务与业务锁外，不能整条流程独占 worker。
- 每次调用前、发布时校验创建者、来源与停止条件，基础取消标志从本项具备，T04 再交付用户控制。报告发布保留换版待复核信息，不修改已有报告或复核状态。
- 持久记录步骤开始、结束、失败与自动重试，记录可获得的模型/供应商和用量，未知值明确为空；总调用预算包含失败尝试，不能叠加父子重试绕过限制。

**验证与完成标准**：替身端到端生成一项分析和一份报告；页面无连接时仍完成。两个 worker、报告提交前后崩溃、旧租约迟到、限额与预算耗尽均收敛；无重复成果或永久处理中。部分分析不自动成稿，撤权/来源失效阻止后续发布，并回归已有上传和分析路径。

## T03：工作台完整入口

**目标**：用户能从现有工作台启动并回看一条完整执行，进入现有分析与报告功能核对成果。

- 先选择资料和分析方式；复用自然语言字段建议及本人常用要求，建议失败时保留输入并允许手工调整。
- 确认区呈现文档清单、字段/维度、报告要求与将创建的成果；用户启动后固定要求。提交失败保留输入，同一提交重发使用原幂等标识。
- 提供本人执行列表与详情，显示真实阶段、错误、分析与报告入口。列表仅展示必要元数据；未完成不显示虚假完成百分比或预计时间。
- 关闭页面、刷新、切换模式后从服务端恢复；切换知识库/账号清理旧范围与迟到响应。采用现有轮询模式即可，不新增通信框架。
- 进入现有报告编辑、依据核对与导出流程，明确“执行完成、报告待核对”；停止条件和来源提示由服务端决定。

**验证与完成标准**：浏览器走通准备、确认、启动、离开、重开、失败和完成，验证分析/报告跳转、范围切换与无权访问；按设计规范核验关键操作、焦点、阅读及窄屏可达性，前端检查与构建通过。

## T04：取消与失败继续

**目标**：用户可以取消未完成流程，故障解决后继续必要步骤，成果与人工编辑保持。

- 取消请求与租约、子分析及发布事务协调；只取消本次执行独占的未完成子任务。取消完成前后分别显示真实状态，已成功成果保留；外部调用无法立即中断时禁止迟到发布。
- 继续前重查成员、全部来源、确认要求和预算；不可恢复原因须说明。暂时故障复用成功检查点；V2 终态分析重跑创建新分析，保存尝试及关联历史，不改写旧任务。
- 报告阶段失败后仅恢复必要步骤；已有报告则返回原成果，不再生成另一份。改变资料或要求通过新执行处理，关联原记录。
- 取消、继续与重复点击均有幂等响应；记录操作者、原因码、尝试和状态事件，不向事件中复制完整输入。

**验证与完成标准**：覆盖排队取消、分析中取消、报告发布竞争、失败后重复继续、权限恢复与来源仍失效；确认停止后无新成果，继续后无重复报告，已有人工章节不被覆盖。浏览器核验取消、继续及错误说明。

## T05：故障、权限与记录核验

**目标**：针对整条链路验证前面切片之间的边界，修复实际发现的问题。

- 覆盖同团队他人/管理员访问执行、步骤、事件和成果，跨知识库伪造关联，撤权与发布、删除与读取/发布的竞争；检查响应正文无旧值、摘录或结论残留。
- 验证资料内恶意指令及伪造工具参数不能改变工具、文档集合或身份；非法模型建议不能成为已确认计划。
- 验证关闭进程、租约失效、结果已提交但回执丢失、子任务已终态但父记录尚未收敛等恢复点；事件、状态与成果能一致恢复。
- 对照事件追溯启动、调用、重试、取消与继续；普通日志和事件不记录私人正文或凭据，来源失效后不会借事件返回摘录。来源换版提示与报告人工复核仍按 V3 工作。

**验证与完成标准**：自动化覆盖必要边界并通过，记录发现与修复；执行适当后端全量检查及前端检查，既存问题与新增问题分开。基本权限、可靠性或数据泄漏失败是功能阻断项。

## T06：真实流程验证与交接

**目标**：用公开材料证明新增自动衔接能够实际使用，留下可复现证据。

- 使用独立样例团队和公开材料，走通提取与对比两种方式，确认真实模型来源；抽查遗漏、差异和引用支持情况，不用接口成功代表内容正确。
- 浏览器完成需求确认、后台执行、离开重开、报告编辑保存与导出，检查页面与文件共用保存内容；另跑一个可控失败和恢复场景。
- 本地重启 worker 验证检查点恢复，记录调用与总耗时、失败和已知限制；真实模型缺少配置或运行失败时如实标记，不能以替身降级后报成功。
- 更新 README、范围采用状态及本清单完成记录，区分工程完成、真实流程验证、人工确认和正式质量验收。

**验证与完成标准**：提供上述实际证据和剩余问题，权限/保存/恢复阻断项清零。少量样例不代替正式题集与人工验收；Compose 迁移、持久化及服务重启留待发布阶段执行。
