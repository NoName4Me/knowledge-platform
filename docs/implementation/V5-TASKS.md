## T01：身份、角色与授权基础

**目标**：建立可复用的最小授权基础，后续入口使用同一规则。

- 核对 `models.py`、`auth.py`、邀请合同、RLS 策略及数据库函数中的两角色假设；新增查阅成员并保留旧角色含义。
- 平台身份与成员角色分别建模，补充账号强制改密和团队状态所需的最小数据合同；前后端同步公开必要的能力与状态。
- 梳理公共读取、资料添加、资料/目录维护、成员管理、私人内容和平台管理的授权调用点。复用现有依赖和业务服务，不建立通用权限框架。
- 更新 API 与 worker 的当前账号、团队、成员关系校验；明确停用或退出对在途任务和发布的影响。本人分析、报告和自动成稿对三种角色均可用。
- 显式初始化首个平台管理员；当前 CLI 只建立团队管理员，不能静默改变既有命令或把现有团队管理员全部升级。提供幂等初始化说明和迁移检查。

**验证与完成标准**：独立 PostgreSQL 验证迁移、三角色授权、平台身份与团队身份相互独立、跨团队及私人内容拒绝、连接池上下文复用。旧账号不被意外赋予平台权限，旧成员仍可上传；新操作未闭环前入口保持不可用。

## T02：个人设置与密码闭环

**目标**：本人可维护账号，平台可按确认规则重置密码。

- 个人设置支持修改显示名称、查看邮箱/团队/角色、校验当前密码后改密；改名跨团队一致，邮箱只读。
- 平台账号列表展示必要身份和状态信息；团队管理员可在成员管理中重置本团队成员。平台与团队路径共用固定临时密码规则，普通成员和查阅成员不能重置他人密码。
- 重置为 `user1234`、标记强制改密与撤销全部旧会话在同一事务完成。重置结果不返回密码哈希，事件不含密码。
- 登录后识别必须改密的状态；服务端限制可调用接口，允许完成改密和退出，拒绝公共业务、邀请接受和平台管理操作。新密码不能仍为临时密码。
- 本人改密成功后撤销旧会话并重新登录。处理并发登录/重置/改密，确保重置前密码或旧会话不会在竞争后重新获得业务访问权。
- 补个人设置与强制改密页面规范，沿用密码管理器、粘贴、键盘和错误保留要求。

**验证与完成标准**：验证普通成员和查阅成员重置被拒绝、团队管理员不能重置其他团队成员；平台和团队重置均撤销该账号全部旧会话，临时密码登录只能改密；直接 API、刷新和深链接不能绕过。浏览器走通改名、正常改密、团队重置、强制改密及失败重试；日志无密码与凭据。

## T03：平台团队管理与停用

**目标**：平台能建立团队、指定负责人，并停用账号或团队而保留数据。

- 补平台管理页面规范；提供团队列表与创建入口，指定初始管理员；已注册账号可建立管理员成员关系，未注册账号复用邀请流程。
- 创建团队、初始管理员关联或邀请与必要事件一致提交。重复点击/请求不产生重复团队或重复成员关系；尚未加入的管理员明确显示为待接受邀请。
- 明确待管理员加入、可用和停用的最小状态及过渡；初始化邀请过期、撤销或目标账号停用时，允许平台重新指定初始管理员，不留下无法管理的可用团队。
- 平台账号管理与团队管理提供停用操作、确认和结果反馈。账号停用影响所有团队，团队停用只影响当前团队，均保留资料和个人成果。
- 停用账号前统筹最后管理员约束，给出需要交接的团队；停用与后台运行、上传、邀请接受及成果发布并发时仍遵循范围规则。
- 跨团队元数据采用受限访问路径，覆盖数据库授权和应用层校验；不得为平台列表开放正文或私人业务表读取。

**验证与完成标准**：平台用户可创建团队并完成初始管理员加入；非平台用户无法直接调用。停用账号阻断全部团队、停用团队不影响其他团队；在途任务明确收敛且不发布未授权成果，数据仍存在。浏览器验证创建、邀请未接受、失败及停用状态。恢复细节在实施前写入状态合同，不擅自增加永久删除。

## T04：团队设置与成员生命周期

**目标**：团队管理员能维护团队和成员，成员能看清本人权限并主动退出。

- 团队设置提供名称、简介、成员、邀请和固定角色权限说明；个人设置显示本人角色和对应权限。
- 邀请支持三种角色，展示待接受、已接受、过期、撤销状态；重新邀请生成新链接并使旧待接受链接失效，不在页面持久展示不可恢复的旧令牌。
- 支持成员角色调整和移除；区分团队管理员动作与本人退出。退出/移除保留账号、公共资料和个人历史，失去该团队访问权。
- 对降级、移除、退出以及 T03 的账号停用统一实现最后一名可登录管理员保护；并发更新须通过事务和约束串行核验。用户看到具体阻塞团队与交接提示。
- 角色改变后前端刷新本人能力；旧标签页和直接 API 使用当前服务端权限。撤销成员关系对读取、运行和发布及时生效，重新加入不自动继续旧任务。

**验证与完成标准**：覆盖邀请三角色、旧链接失效、非受邀邮箱、非管理员调用、同用户跨团队不同角色、本人退出，以及最后管理员并发降级/移除/退出/账号停用。浏览器完成邀请、调整、退出和错误反馈；成员管理接口不提供密码重置或私人内容读取。

## T07：知识库可见范围与独立授权

**目标**：以知识库作为资料与知识产品的统一权限边界，同时保留团队隔离和个人成果隔离。

- 已知有效团队角色均可创建团队可见或私人知识库；知识库创建与创建者 `manage` 授权在同一事务完成。
- 团队库默认权限为管理员 `manage`、普通成员 `edit`、查阅成员 `view`；可设置团队默认 `view/edit/manage`。个人授权只能提高有效权限。
- 私人库只对创建者和明确授权成员可见；团队管理员不会自动访问。创建者固定 `manage`，可以为成员授予 `view/edit/manage` 或撤销。
- 知识库权限统一约束资料、原件、目录、问答、分析、笔记、报告、自动成稿及后台发布。API 重新校验授权，RLS 阻止直接 SQL 读取缺失授权的资料与私人内容。
- 长连接逐段复核授权；撤权后流式轮次、排队/运行中的分析、汇总与自动执行收敛到失败。上传对账从上传者、知识库创建者或当前授权成员恢复用户上下文，不使用跨团队超级权限。
- 仅本人上传者可重试本人失败资料；前端重试入口由知识库编辑权限控制，服务端继续校验上传者身份。
- 知识库设置弹窗展示实际有效权限和来源；切换可见范围与替换成员授权失败时保留表单并显示原因。

**验证与完成标准**：自动化覆盖成员建库、管理员不可见私人库、单独授权与撤权、团队默认权限、个人提权、离开团队、直接 SQL 读取隔离、流式与排队任务撤权收敛、上传对账。前端完成 lint、测试与构建；浏览器检查桌面与 375px，确认入口和权限标签一致且无横向溢出。

## T05：工作台权限与操作入口统一

**目标**：修复文件夹上传入口不一致，落实完整权限矩阵。

- 核对 `DocumentPanel.tsx`、知识库入口和后端资料/文件夹路由，将添加资料与目录维护分别按操作能力控制，替换混用的 `canDelete` 条件。
- 普通成员在全部资料和已有文件夹均可上传、粘贴、导入；界面明确目标文件夹。仍允许其重试本人失败上传。
- 查阅成员看不到公共资料写入动作，直接调用上传、文字/网页导入、重试、换版、移动、排序、改名、删除和知识库/目录管理均被拒绝。
- 公共资料维护由团队管理员操作；桌面菜单、窄屏入口、详情、拖拽及批量路径采用相同规则。保留查阅成员的问答、本人分析/自动成稿/笔记/报告与导出功能。
- 更新首页、工作台对应页面规范；页面显示和拒绝原因使用“查阅成员、普通成员、团队管理员”，避免继续把所有非管理员统一展示为可上传成员。

**验证与完成标准**：按 V5 权限矩阵运行三角色接口测试，验证上传目标文件夹、所有写入路径和同用户跨团队不同角色。浏览器分别登录三种角色检查桌面/窄屏及旧页面撤权后行为；前端检查与构建通过，已有 V1–V4 主流程无权限回归。

## T06：综合核验与交接

**目标**：以可复现证据交付账号、团队和权限管理闭环。

- 使用独立样例建立至少两个团队，包含同账号跨团队不同角色及一个没有业务团队成员关系的平台管理员；用公开资料验证查阅、上传、分析和报告。
- 串联“平台创建团队 → 初始管理员加入 → 邀请三角色 → 调整角色 → 文件夹上传 → 退出/移除 → 重置密码并强制改密 → 停用”的实际流程。
- 集中复核旧会话、重置竞争、最后管理员竞争、停用/退出与成果发布竞争、邀请接受时状态变化和 RLS 隔离。
- 检查管理记录能追溯目标、操作者和结果，不含密码、令牌或私人正文；平台和团队管理员均无直接读取他人私人内容的管理接口。
- 按 README 执行适当的后端全量检查、前端测试/lint/build；浏览器验证桌面、窄屏、刷新、深链接、空状态与失败重试。记录实际运行环境和证据，不把接口替身验证当成真实流程或正式内容质量验收。
- 更新 README 与本清单实际状态，补充首个平台管理员初始化、密码重置及停用操作说明。发布阶段再补 Compose 迁移、持久化与重启核验。

**验证与完成标准**：权限矩阵全部有对应验证，账号/团队/个人设置闭环可复现，越权与状态失效无阻断问题；已实施、实际验证、待确认细节及发布待办分别记录。
