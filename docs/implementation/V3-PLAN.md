# V3 规划：报告交付与知识沉淀

状态：2026-10-21，V3 主流程和真实使用反馈修复已完成。本文记录实际交付范围、验证结果和保留边界；未列入完成项的能力不因规划存在而视为已实现。

## 阶段目标

在已有文档问答和多文档分析上，形成持续使用的工作流程：

**接入资料 → 阅读与提问 → 分析并核对 → 保存知识 → 生成、修改和导出报告 → 更新资料后复核成果。**

V3 的第一轮交付仍是报告生成、本人审阅修改和 Word 导出；知识沉淀、阅读与分析入口随后分批交付。每批完成即可试用，不等全部功能齐备再交付。

## 开始条件与现状

可以开始。V1 已有资料上传、解析、问答和来源定位；V2 已有提取、对比、结果保存和依据；工作台、模型适配与后台任务可以复用。用户已用一份真实文档试用，反馈基本能用。

正式质量评测、容量测试、人工盲审和发布部署验收不作为启动 V3 的前置任务。保留现有未验收记录，开发中用少量真实资料验证当前功能，发现具体问题再修正。

静态代码核查发现三项与核心效果有关的限制，纳入针对性补齐：

- 会话历史已保存，但检索及生成只传本轮问题，连续追问缺少前文。
- DOCX 提取只读取正文段落，未读取普通表格。
- 词项评分只重排向量候选，缺少独立关键词召回；编号和专名的实际漏检情况尚需样例确认。

上述代码观察不等于已复现所有质量故障。先验证与修复相关场景，不借机重做整个检索或解析系统。

## 纳入 V3 的能力

| 能力 | 本阶段要做到什么 |
| --- | --- |
| 连续追问与资料范围 | 结合前文理解“它有哪些限制”等问题，再检索原文；支持选择文档或目录作为问答范围，默认仍可问整个当前知识库 |
| 报告生成 | 先从一项本人已完成、来源有效的 V2 分析生成报告；随后支持同一知识库内直接选资料，以及选定问答和知识笔记作为起点 |
| 报告要求与大纲 | 填写主题、用途、重点和篇幅，提供可调整的大纲；先使用简单默认结构，不建设模板平台 |
| 审阅、编辑与成果管理 | 本人核对依据，修改标题、章节正文与顺序，保存并重新打开；支持报告改名、查找和删除；整篇重新生成保留旧稿，章节 AI 修改先预览再采用 |
| 导出 | 第一轮完成 Word；后续补 CSV/Excel 表格结果导出和 PDF。文件包含对应内容、引用编号、来源名称及原文位置 |
| 知识笔记 | 保存原文摘录、选定回答和自己的理解；支持编辑、整理、查找、删除及带依据复用，用于后续问答或报告 |
| 自然语言分析要求 | 用户描述目的，系统建议字段或比较维度，用户确认或调整后执行；可保存并复用自己的常用字段和报告要求 |
| 文档导读与正文搜索 | 提供资料摘要、内容结构、关键概念和建议问题；正文搜索返回命中片段、来源位置及相邻上下文，方便阅读核对 |
| 待核实与材料缺口清单 | 根据分析或报告目的，整理本次发现的缺失字段、矛盾说法和依据不足之处，给出需补充的材料方向，并可逐项核对 |
| 轻量资料接入 | 支持粘贴文字和导入公开网页正文，保存来源信息，进入现有知识库；网页首版仅处理选定单页，不递归抓取站点 |
| 资料更新与成果复核 | 提供手动更新或关联替换资料的入口，标出相关笔记、分析和报告需要复核；由用户选择重新生成，保留人工修改，不静默覆盖成果 |

首版笔记和报告沿用本人可见的范围；团队共享、评论和协作审批暂缓。笔记中的原文事实、模型归纳和人工补充要能区分，保存了一段生成内容不代表它自动成为原始证据。

## 架构重点

沿用现有模块化单体、PostgreSQL、worker、模型和存储适配器、本地应用进程与工作台。围绕当前切片增加必要能力，不新增服务、通用 Agent 或工作流框架。

- **资料、知识笔记与报告分工明确。** 资料承载原始内容；笔记保存摘录和理解；报告组织交付成果。直接选资料生成报告不强制用户先手工配置提取字段。
- **内容独立保存、来源保持关联。** 报告和笔记保留所用资料及依据；修改成果不回写 V2 结果，重新分析不自动覆盖已有人工内容。
- **提问与全文任务分开处理。** 问答可检索相关片段；全文导读和多文档综合需实际覆盖相应内容，不能用少量相关片段冒充完整阅读。超出当前处理能力时明确说明覆盖限制。
- **人工编辑不等于依据已重新验证。** 编辑事实性内容后提示复核；模型不能编造引用。缺口和矛盾只描述本次材料中发现的情况，不承诺全局无遗漏，不代做行业业务裁决。
- **页面和文件共用保存内容。** 导出负责排版，不再次生成一份不同报告。先支持标题、段落、列表、表格和参考来源，Word 可复用已有 `python-docx`。
- **来源更新显式处理。** 更新和重新生成由用户触发；来源删除遵循现有有效性规则。保留既有 V2 失效行为，不顺带建设完整文档版本、自动通知或后台同步平台。

## 开发与交付顺序

| 批次 | 交付内容 | 用户可验证的结果 |
| --- | --- | --- |
| 0. 核心问答补齐 | 连续追问、选定资料范围；用少量样例核查 DOCX 表格与编号检索，针对性补齐 | 连续提问不用重复背景，回答依据来自选定范围，常见表格内容和编号可被正确找到 |
| 1. 第一轮报告交付 | 有效分析生成报告 → 本人核对与编辑 → 保存、重开 → Word 导出，带基本报告管理 | 得到一份能修改、能核对、能拿走使用的真实报告 |
| 2. 知识沉淀与分析入口 | 可编辑知识笔记，问答/摘录保存与复用；自然语言建议分析字段，保存常用要求 | 有用结论不只留在聊天里；下一批资料不用重新配置同样要求 |
| 3. 阅读与综合报告 | 直接选资料或笔记生成报告；文档导读、正文搜索和位置核对；报告附本次待核实与材料缺口 | 从陌生资料开始能读懂、找到依据、形成报告，并知道哪些结论仍缺材料 |
| 4. 接入与更新 | 粘贴文字、公开网页单页导入；手动更新/替换关联及受影响成果提示 | 日常材料容易进入知识库，资料变化后能找到需要复核的成果 |
| 5. 成果增强 | 单章节 AI 修改候选及采用；CSV/Excel 表格导出、PDF 导出 | 保留人工修改，结构化结果可继续使用，报告可选择所需文件格式 |

批次是优先顺序，每批再按一个可观察行为拆分，不要求形成巨型提交。批次 0 中与当前切片无关的问题不阻塞批次 1；以后也不把全部阅读、接入或更新能力当成报告生成的前置依赖。

### 批次 0 实施记录（2026-10-20）

- 会话轮次保存资料范围；请求可选择当前知识库的一份或多份已完成文档。后端复核团队、知识库与文档状态，跨库、重复、未完成或已删除资料会被拒绝。
- “全部资料”继续作为默认范围；问答页可直接切换为“指定资料”。资料新增、删除或处理状态变化后，失效选择会从界面范围中移除。
- 最近四轮已完成问答作为理解上下文送入生成模型，并参与追问检索；模型被明确限定只能以本轮原文片段作为事实依据。每轮范围独立固化，重复请求问题或范围变化会被判为冲突。
- DOCX 按正文顺序读取普通表格，单元格以“表头：值”或行内文字进入现有切块流程，位置写作“第 N 张表 · 第 M 行”；不承诺复杂合并、嵌套或版面结构还原。
- 检索在向量候选之外独立查询关键词命中的片段并融合排序，补上编号、专名和缩写不靠近向量最近邻时可能漏检的情况。
- 验证：批次 0 当时后端全量为 **188 passed**。V3 收尾时重新执行后端全量 **200 passed**，`ruff`、`mypy`、类型生成检查通过；前端 **10 tests passed**，lint/build 通过（保留原有 AuthContext 警告）。浏览器用独立样例验证指定一份资料、引用、连续追问和范围面板；正式质量评测与人工盲审仍未执行。

## 验证与投入控制

- 每个切片用少量真实资料验证关键行为，形成可操作的前后端流程，由用户试用反馈决定针对性修正。
- 必要测试围绕当前功能的内容正确性、保存、引用关联、编辑不丢失、导出一致性和基本访问隔离；测试使用独立数据库，不以测试数量衡量进展。
- 继续使用本地 API、worker、前端进程。CI 保持现状，部署、重启、容量及发布验收集中在发布阶段。
- 实现界面时复用现有设计系统、tokens、工作台和依据抽屉，按规范做必要的浏览器核验；优先保证桌面主流程，不主动扩展多尺寸精修。
- 不将核心功能推进变成安全加固、CI 建设、部署验证或全量故障演练项目；基本权限、日志、异常处理和保存仍随功能完成。

## 暂缓范围

OCR、复杂表格与图表理解、完整文档版本管理、大量外部连接器、全网深度研究、知识图谱、音视频与幻灯片生成、专门测验系统、自动记忆、定时摘要、实时共同编辑、多人审批、复杂排版和模板平台均暂缓。

V4 保留工具调用与自动执行方向，等出现明确操作场景再细化；Text-to-SQL 仍不属于本项目。

## V3 完成记录（2026-10-20）

### 已完成

- 连续追问使用最近问答上下文理解指代，检索仍只以本轮原文片段作为事实依据；可指定资料范围，跨库、失效和未完成资料会被拒绝。
- DOCX 表格按正文顺序进入解析；关键词独立召回与向量结果融合；粘贴文字和公开网页单页可进入同一知识库。
- 知识笔记支持本人新建、编辑、查找、删除、关联资料和保存问答依据。
- 报告支持从完成分析、资料或笔记生成；可编辑名称、用途、重点、篇幅、章节标题、正文和顺序，保存后重开内容保持。
- 单章节 AI 修改先生成候选，预览后采用；整篇采用不自动保存。报告列表支持按名称查找。
- 报告支持 DOCX、PDF、XLSX、CSV 导出，页面与文件复用同一份保存正文，导出包含章节与参考来源。
- 报告显示待核实和材料缺口，可逐项核对；常用分析字段和报告要求可保存并重新套用。
- 资料详情提供导读、结构、关键概念、建议问题和正文搜索，并显示命中上下文及位置。
- 管理员可用新文件创建新资料版本；原资料标题保留，选择器显示文件名和新版本标识。相关笔记、分析和报告的影响数量会明确提示。
- 资料换版会持久标记引用旧资料的个人报告待复核，并显示新版本复核说明；只有用户勾选确认后保存才清除标记，报告正文不会自动改写。
- 真实配置模型时直接生成可读报告且引用编号受约束；模型失败不回退为伪装成稿。未配置模型时显示明确标注的初始框架。

## 真实使用反馈收尾（2026-10-21）

### 已修复

- 上传支持兼容 `.doc`。旧版 Word 通过 LibreOffice headless 转为 DOCX 后进入现有解析流程；未安装转换器时返回明确错误，不把文件误判成已处理。
- `.html`、`.htm` 和网页导入使用同一解析入口。导入后保留网页标题与来源地址，不再出现“允许导入、处理时却声称格式不支持”的自相矛盾。
- 目录和资料共用同级排序，支持拖动到上方、下方和目录内部；移动与排序作为一次事务保存，刷新后顺序保持。目录的上下边缘表示同级插入，行中部表示移入。
- 重命名只编辑文件名主体，扩展名固定显示，页面不再允许通过输入框误改资料类型。
- 前端图标统一使用 **Tabler Icons**：操作、状态、导航与文件类型使用同一套线条图标，文件类型辅以低饱和分类色；目录不再重复显示文件夹图标。
- 目录行与同级资料行使用统一左边缘。目录“更多”菜单增加“上传资料、粘贴文字、导入网页”，保留重命名与删除，文案不再附带“到这里”。
- 清理资料树后端的过期排序实现和冗余验证代码，只保留当前页面实际使用的混合排序与原子移动路径。
- 修复浏览器残留旧会话 Cookie 时无法重新登录的问题；登录接口在同源且预登录令牌有效时可替换旧会话，前端也能展示后端结构化错误信息。

### 验证

- 真实浏览器确认 Word 类型图标、目录与文件对齐、目录菜单和刷新后的排序持久化；真实 DOCX 恢复为 `ready`，既有分析任务恢复为已完成且不再显示来源失效。
- 定向后端回归 **20 passed**，覆盖旧会话登录、解析和资料树写入。
- 最终检查：后端全量 **204 passed**；前端 **13 tests passed**；`ruff`、`mypy`、类型生成一致性、前端 lint/build 与 `git diff --check` 均通过。

### 资料树可用性修正（2026-10-21）

- 目录名和文件名固定单行，过宽时显示省略号；悬浮通过原生标题展示完整名称。
- 移除资料树顶部“新建目录、上传资料、粘贴文字、导入网页”操作区。“全部资料”行提供管理菜单，目录行保留对应操作。
- 修复拖拽后只剩“全部资料”的问题：排序事务提交后恢复团队 RLS 上下文，接口会返回完整目录集合；前端提交“移入”和“移到根级”时也包含目标同级列表，失败时重新读取服务端树。
- 资料树搜索改为带左侧放大镜的胶囊输入框，移除顶部“资料目录”标题块。数量在“全部资料”名称旁显示，根级和目录行的新建、更多操作改为常驻。
