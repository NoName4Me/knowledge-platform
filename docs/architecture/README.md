# V1 实施指导

状态：目标约束，不代表现有实现已满足。产品范围以 [V1-SCOPE](../../V1-SCOPE.md) 为准，技术路线以 [架构总纲](../../V1-ARCHITECTURE.md) 为准。本文只补充后续模型不能自行猜测的边界，不要求重构目录或引入新框架。

## 已定与待定

- 保留模块化单体、React/TypeScript、FastAPI、PostgreSQL/pgvector、数据库持久任务及独立 worker。当前开发和功能验收在 Mac mini 上以 API、worker、前端本地前台进程运行；项目自身 Compose 服务推迟到发布阶段做部署与重启验收。
- **文档团队共享；问答会话和历史仅创建者可见，团队管理员也不能查看他人问答。** 用户于本轮确认。
- 生成模型固定为 DeepSeek `deepseek-flash`（当前官方标识，DeepSeek V4.1 Flash）；嵌入固定为本机 Ollama 的 BAAI/bge-m3（1024 维）。真实凭据只从环境变量读取，测试默认使用确定性替身，真实结果单独验收。
- 原始文件固定走 S3 兼容接口；本地开发与验收使用 OrbStack 托管的 Garage，其他本地基础服务也统一由 `~/jonge/infra` 管理。Ollama 的启动、固定模型准备和健康检查同样纳入该基础环境，保留 macOS 本机应用与默认模型目录；项目只维护连接配置及向量兼容性要求。生产可在不改业务代码的前提下替换兼容供应商。CSV 等非文档场景不得复用 S3 作为查询数据库。
- 中文分词、混合检索、重排以同一题集的效果决定是否引入；不默认全部建设。V2–V4 只保留扩展位置，不预建通用 Agent/工作流框架。
- 2026-10-19 固定 60 题评测后，混合检索（向量召回 + 中英文词项召回，见 `retrieval_candidate_k`、`retrieval_distance_limit`、`retrieval_min_lexical_score`）已作为当前基线；重排仍未接入，继续由同一题集决定是否引入。

## 模块责任

沿用现有文件，按职责维护；只在当前任务确有需要时拆分。

| 部分 | 负责 | 不应负责 |
| --- | --- | --- |
| 身份与团队 | 登录、会话、成员关系、邀请和角色校验 | 文档解析、模型调用 |
| 文档与知识库 | 上传、额度、元数据、原件访问、删除与重试 | 自己运行耗时解析 |
| 任务与处理 | 领取/续租/回收、解析、分段、嵌入、完整发布 | 决定用户权限、读取私人问答 |
| 检索与问答 | 限定资料范围、上下文、生成、引用、本人历史 | 全库召回后再过滤、执行模型工具 |
| 基础适配器 | 数据库、对象存储、模型、配置、日志 | 擅自提交跨模块业务事务 |

应用服务拥有事务；路由负责协议转换。存储和模型通过小接口隔离，至少支持写/读/删除/查对象，以及嵌入/生成；错误显式区分临时故障、输入错误与配置错误。外部调用不持有数据库业务锁。无需为这些原则新增通用仓储框架。

## 数据与权限底线

V5 已确认新增平台身份、查阅成员及账号/团队状态管理，权限变化以 [V5 范围](../../V5-SCOPE.md) 为准，按 [V5 任务清单](../implementation/V5-TASKS.md) 实施；以下两角色描述保留为 V1 基线，不代表 V5 已实现。

1. 团队数据带 team_id；关联关系用包含 team_id 的复合约束，文档、片段、会话与引用还须属于同一知识库。不能只靠前端传来的团队值。
2. 每次请求查当前成员关系；成员移除后下一次访问失效。普通成员可以上传、重试自己的失败上传；管理员管理知识库、删除资料、移除成员；并发操作仍须保留至少一名管理员。
3. 会话固定绑定 team_id、knowledge_base_id、created_by。读列表、单轮、引用、继续提问都检查本人；仅校验同团队不够。非本人会话与不存在的会话统一返回 404。
4. RLS 与应用授权同时存在；API/worker 使用非所有者、不可绕过 RLS 的运行角色，迁移账号独立。每次从连接池取用连接都要重新切换运行角色，每个事务再设置局部团队上下文，缺失时拒绝；连接归还池会重置角色，只在首次 `connect` 时设置不足。验证连接池复用不会回到迁移账号或串团队。worker 不因清理引用而获得私人问答正文读取权。
5. 原件保持私有，经授权代理访问；删除来源后历史答案保留，但来源摘录不再返回。已发送给客户端的内容不能承诺撤回。
6. 嵌入版本与向量维度显式记录；切模型不能直接混查旧向量，须有重新索引与切换方案。
7. 本机 PostgreSQL 容器只运行一个实例，按项目隔离数据库、迁移账号和运行账号；本项目迁移账号 `kp_migrator` 与受限运行角色 `kp_app` 分离，不能复用其他项目的数据库超级用户。

## 三条关键流程

### 上传与删除

- 上传先在事务内预留团队额度并创建记录，再写对象，最后原子更新状态并创建处理任务。并发上传不能分别读取同一份剩余额度后都放行。
- 上传具有幂等键；同键同文件返回原记录，同键不同内容拒绝。对象写入成功、数据库提交失败时，由对账恢复或清理；服务不可用不能被当作“对象不存在”。需跨团队发现候选记录时，只允许受限数据库函数返回 ID/团队 ID，之后逐条恢复团队上下文，不能为方便调度放开业务表 RLS。
- 删除先提交不可见状态、使处理任务失效，再后台清理对象与片段。清理失败不能让资料复活；额度只释放一次。上传迟到写入也须由补偿或对账清理。
- 最少区分上传中、待处理、处理中、可用、失败、已删除。可以映射现有状态名，不为了统一拼写强制迁移。

### 任务执行

- 每次领取生成新的租约令牌；续租、成功、失败、重试都校验当前令牌、未过期租约和处理版本。旧执行者的迟到结果不能覆盖新执行者。
- 自动重试有次数和退避上限；最后一次执行中崩溃也要收敛到失败，不能永远处理中。人工重试与自动尝试次数分开记录。
- 解析与嵌入期间产物不可检索；全部成功后，发布片段、文档可用状态和任务成功在同一事务提交，且再次检查未删除。不同执行尝试的产物不能混合发布。
- 领取仅锁任务并立即提交；联动发布/删除时统一先锁文档再锁任务。需要额度锁时先锁额度。外部调用在事务外，心跳独立进行。

### 问答与引用

- 先按团队、当前知识库、可用文档和已发布版本限定范围，再排序和截断。历史回答只作对话上下文，不能作引用证据。
- 没有足够依据时明确说明不足；模型或存储故障返回失败，不能伪装成“资料不足”。引用只能指向本次提供的片段，保留 PDF 页码或其他格式的段落位置。
- 流式内容是草稿；最终答案与校验后的引用一起持久化。生成结束前复核成员、会话所有权和来源有效性；来源已删除则本轮失败，不继续发布旧引用。
- SSE 使用 `POST .../turns/stream`，成功事件顺序为首个 `turn`、若干 `delta`、终态 `turn`，随后发送 `done`；失败发送带 `error_code` 的 `error`。客户端断开后保留已生成草稿，重新进入先读轮次；遗留 `answering` 由超时收敛为 `interrupted`。最终发布时成员关系、会话所有权或来源任一失效即失败，不得返回 `completed`。
- 一次提问有唯一请求标识，重复提交不重复调用模型；断流后读取已保存状态。失败或中断不能存为成功；进程崩溃遗留的进行中轮次必须超时收敛。同一会话的提问创建须锁住会话行，并由“每会话最多一个 `answering`”的部分唯一索引兜底；不能只做先查后写。
- API schema 是前后端唯一合同；客户端由 OpenAPI 生成，SSE 事件另用共享 schema 约束。统一错误码及请求标识。接口调整与前端消费者在同一交付批次完成。
- 请求日志记录请求标识、方法、路径、状态码和耗时，不记录正文、查询参数、Cookie、凭据或问答内容。当前单 API 进程部署使用进程内固定窗口限流：登录按来源与邮箱、问答按用户；响应为 `429` 和 `Retry-After`。扩容为多 API 实例时须改为共享限流状态。

## 执行与验收

按 [任务清单](../implementation/V1-TASKS.md) 一次完成一个切片。开始时只补该任务所需的字段/约束、接口输入输出、状态转换和错误结果；这些属于工程细化，不再预写全项目逐字段规格。涉及供应商、部署拓扑或产品权限变化才交用户决定。

每个切片给出改动、验证结果与剩余限制；已有代码和旧的“已完成”描述不能代替证据。最低检查：

- 两个团队交叉访问、同团队两人互猜会话、管理员访问他人历史、成员移除和连接池复用均被正确拒绝。
- 两个 worker 竞争、过期执行者迟到、最后一次崩溃、上传中断、删除与发布并发均有确定性测试。
- 四种文件的定位可核对；扫描 PDF、损坏/超限输入明确失败；删除来源不再显示摘录。
- 常规测试用替身，真实模型另跑既定 60 题与 5 并发验收；不能降低总纲中的正确性、引用和延迟目标。
- 发布阶段再用 Compose 验证原件、数据库、索引和问答持久化及服务重启；迁移、运行凭据分开，日志脱敏。当前本地开发不把项目应用容器作为运行前置条件。不将异地备份与云部署加入当前门槛。

本文未指定新的服务、数据库表全量布局或大量超时默认值；在对应任务实现时用最小方案落地并验证。
