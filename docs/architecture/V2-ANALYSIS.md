## 现有代码与复用边界

2026-10-20 已检查以下入口；实施时先核对当前代码，表中路径是导航，不是要求重构的目录蓝图。

| 入口 | 可复用内容 | V2 必须补充 |
| --- | --- | --- |
| `backend/app/models.py`、`backend/alembic/versions/` | 文档、资料片段、迁移与复合约束模式 | 分析任务、逐文档执行、字段/结论/依据的持久化及 RLS |
| `backend/app/tasks.py`、`worker.py` | 租约、回收、有限重试和 worker 调度模式 | 现有 `ProcessingTask` 强制关联单文档，不能直接作为批量分析记录；增加专用分析任务执行路径 |
| `backend/app/answering.py` | 现有供应商配置、HTTP 调用方式及测试替身思路 | 当前接口返回问答正文，不能保证结构化输出；增加小型分析适配接口及校验 |
| `backend/app/auth.py`、`db.py` | 成员校验、受限运行角色、事务级团队及用户上下文 | 本人分析与后台执行身份绑定 |
| `backend/app/routers/documents.py`、`upload_service.py` | 来源访问、逻辑删除及清理 | V2 读取和发布对来源的实时校验；不扩大管理员对私人内容的读取权限 |
| `backend/app/schemas.py`、`frontend/src/lib/api.ts` | 后端 schema 和前端请求入口 | V2 类型、错误及状态契约；现有前端类型为手写，T01 补足 V2 的最小类型生成入口 |
| `frontend/src/pages/WorkspacePage.tsx`、`components/` | 团队/知识库范围、资料列表及依据展示方式 | 分析入口、表单、历史、进度和结果表 |
| `backend/tests/`、`evaluation/` | 独立 PostgreSQL、权限/竞争测试和真实评测分离 | V2 标注数据、协议替身及真实质量评测 |

保持模块化单体、现有 PostgreSQL、生成模型和对象存储。当前以本地 API、worker、前端进程运行，发布阶段再使用 Compose 验证部署；分析服务拥有事务，路由只处理协议，分析适配接口与原问答接口分开，避免问答提示词承担 JSON 提取。无需增加 Redis、向量库或框架。

## 最小数据责任

以下是必须保留的信息，不要求在规划阶段锁死所有表名与字段。T02 使用迁移实现，可按职责合并字段结果的存储，但可查询归属、外键及状态约束不能只靠自由 JSON。

| 对象 | 必须保存 |
| --- | --- |
| 分析任务 | 团队、知识库、创建者、类型、标题、固定字段/维度定义、文档清单、提交幂等标识及请求指纹、状态、阶段、时间、错误码、来源任务 ID（如有） |
| 分析文档执行 | 所属任务及同范围文档、发布文本指纹、预期/完成片段数、逐文档状态、当前租约与尝试次数、下次重试时间、失败原因 |
| 字段结果 | 文档执行、固定字段 ID、状态、类型化值、原始表达、单位/日期精度（如适用）、歧义说明、依据关联 |
| 对比结论 | 维度 ID、共同点/差异/待核实类别、结论正文、参与文档、依据关联 |
| 分析依据 | 同任务/文档范围、资料片段身份、页码或段落位置，以及发布文本指纹；清理片段后仍能显示失效状态 |

- 每个字段有稳定 ID；名称仅用于展示，不能按模型返回顺序或重名名称关联结果。字段名去空白后重复、空说明/名称、未知类型、空列表等在创建时拒绝。
- 来源指纹基于按顺序排列的已发布片段内容及定位信息；保存指纹及覆盖清单，避免复制一套完整原文。当前文档没有显式发布版本字段，可用该方式实现分析快照，无需顺带建设文档版本管理。
- 重索引即使内容不变但片段身份改变，也须证明依据仍对应本次快照；无法证明则失效，不能自动挂到新片段上。失效状态不可因来源随后重新可用而自动恢复。
- 请求指纹包含任务类型、知识库、文档集合及字段/维度定义。创建请求按团队、创建者、幂等键唯一；同键同输入返回原任务，同键不同输入返回冲突。
- 新建分析、固定输入及入队在同一事务完成。重新运行使用新的幂等键和新任务 ID，旧任务结果保持不变。

## 覆盖与结构化输出

1. 读取所选文档全部已发布片段，按顺序生成有界批次。先校验任务及输入预算；大于模型上下文的片段也要切成带父定位的子段。原始片段重叠不能造成列表项重复。
2. 每批要求模型只返回本次字段 ID、候选值/原始表达、歧义、依据 ID；资料作为不可信数据，文档指令不得改变任务或获得工具能力。
3. 服务端校验 JSON 结构、字段集合、类型、值长度、依据归属及摘录是否来自对应片段。模型生成的页码、文件名或陌生 ID 不作为真实依据。
4. 合并该文档所有批次候选；记录覆盖情况。不能只保留前几个候选后声明完整；候选或输出超预算时显式失败。
5. 对重复内容去重；不同条件、时间、对象下的候选保留区别。无法确定一个字段值时标记待核实并保留相关依据，不能随意选一个。
6. 仅当全部批次成功且没有有效候选时才记未提及；某批次失败则该文档失败，未完成的中间结果不作为最终字段发布。
7. 复核当前成员关系、来源快照与租约后，在同一事务发布该文档完整字段与成功状态。结果结构合法只代表协议通过，语义支持仍需真实题集评测。

数字默认只提取明确表达，不做金额换算、单位折算或业务推导。日期若只有“2026 年”不能补成“2026-01-01”；需要严格日期但依据不足时使用待核实状态及原始表达。列表只支持平面文本项，且每项能追溯依据。

## 对比流程

- 比较维度作为提取字段，先得到逐文档结果，再生成跨文档结论。类型默认文本，也可按创建时声明的类型处理。
- 仅使用本任务已校验的提取结果和其对应证据；汇总时不能重新全库检索或引用其他历史分析。
- 每条结论列明参与文档和条件。差异至少关联两份文档的对应值及依据；共同点也要列明支持该结论的文档，不能从两份相同推广到全部。
- 某文档未提及某字段，只能说明“该文档未找到该项”，不能认定它与有值文档冲突。该缺失判断的依据是完整处理记录，不伪造一条原文引用。
- 任一文档失败时，保留成功文档的提取表与不完整提示，首版不生成全局对比结论。所有文档成功但对比阶段失败，也保留提取表并标记部分成功。
- 汇总输入超预算时，首版允许明确结束为部分成功并说明原因，不静默丢弃文档或字段；分层汇总只在确有需要时实现，不预建编排平台。

## 状态与恢复

### 任务状态

| 状态 | 含义 |
| --- | --- |
| `queued` | 已保存，等待执行 |
| `running` | 至少一个执行阶段正在进行或等待有限自动重试 |
| `completed` | 提取模式所有文档成功；对比模式还要求汇总成功 |
| `partial` | 已结束且有可用提取结果，但有文档或对比阶段失败 |
| `failed` | 已结束且没有可用提取结果，或创建者权限已撤销 |
| `invalidated` | 至少一份所选来源已删除或快照失效，全部结果停止展示 |

字段“未提及”“待核实”是成功处理的业务结果，不等于任务失败。任务状态、当前阶段、来源有效性和文档计数分别返回，不由前端猜测。`completed`/`partial` 后仍可转为 `invalidated`；终态任务的重新运行始终创建新任务。

### 执行要求

- 专用分析执行记录复用 V1 租约模式。每次领取新令牌，续租、检查点和发布校验任务、当前令牌及有效期；旧执行者迟到不得覆盖新结果。
- 自动重试只针对暂时故障，次数、退避和总调用预算有上限。结构非法可有限重试，耗尽后归为模型输出错误；权限、来源失效、输入超限不自动重试。
- 已完成文档作为检查点；其他文档失败重试不重新处理成功文档。首版可在单文档内从头重试，但累计调用和用量包含失败尝试。
- 领取后立即提交；外部模型调用在无业务锁的事务外进行，心跳用独立短事务。发布按“文档 ID 排序锁来源 → 分析任务 → 执行记录”的一致顺序加锁；跨多个来源的路径均保持此顺序。
- 多 worker 竞争不能重复发布；最终一次崩溃、汇总崩溃及仅剩终态子任务时，均有回收或对账机制推动父任务结束，不能永远显示 running。
- worker 在解析任务和分析任务之间公平轮询；每次分析执行一个有界文档或汇总阶段后归还调度，不能在一次领取中循环跑完整批文档。单次模型调用不可抢占，其超时必须有界。先用现有 worker 进程，不扩展部署拓扑。
- 每用户/团队活动任务数、文档/字段数、文本量、模型调用数、输出量、超时均由服务端有界配置控制。并发额度的检查与占用原子化，任务结束或失效后只释放一次；边界测试验证不能通过并发提交绕过。
- 单次外部调用可能已经执行但回执丢失，不能承诺绝对不重复计费。保证有限重试、结果幂等，并如实记录可获取的调用及用量。

## 权限与删除并发

- API 运行角色保持受限，分析表采用团队 + 创建者 RLS；关联包含同团队、知识库及任务归属约束。跨知识库关联在写入层校验，关键关联用数据库约束兜底。
- 列表仅本人；同团队其他成员及管理员猜任务/字段/引用 ID 统一返回 404。无团队权限继续沿用现有认证错误约定。
- 调度跨团队仅通过受限函数领取必要身份信息（执行 ID、团队、创建者、令牌），不开放业务表跨团队扫描。worker 按领取的任务绑定团队和创建者上下文，不能取得私人问答的额外读取权；受限函数固定 search_path、检查状态并只返回调度所需信息。
- 开始处理、每次模型调用前及最终发布重新检查创建者仍为团队成员。每次提交后，下一事务重新设置用户与团队上下文。
- 结果读取先复核完整来源集合，任一失效即返回 invalidated 的受限视图；列表预览、独立引用端点和缓存执行相同规则，隐藏不应只发生在前端。
- 删除事务提交后，后续读取不能返回分析字段、摘录或结论；读取时实时校验兜底，后台再收敛持久状态。发布事务锁定来源并检查删除，删除先提交则发布失败，发布先提交则删除后读取仍隐藏。
- 删除清理通过来源关联定位任务/状态所需的最小信息，不授予管理员读取私人字段或要求正文。失效后的后台残留中间产物按有界清理策略移除；清理失败不影响即时隐藏，不声称是备份恢复能力。

## API 与界面交付

首版采用短请求创建任务、分页列表/详情轮询；不复用问答 SSE，不新增 WebSocket。路由名称可沿用现有风格，必须覆盖以下行为：

| 操作 | 关键合同 |
| --- | --- |
| 创建 | 类型、显式文档 ID、字段/维度定义、幂等键；202 返回任务 ID；输入无效不入队 |
| 本人列表 | 限定当前知识库、分页；只含标题、状态和计数等元数据，避免预览泄漏 |
| 详情 | 固定输入、阶段、逐文档状态、覆盖与错误、已发布结果及来源有效性；失效时仅元数据 |
| 核对依据 | 校验本人及来源实时有效；只返回该结果授权的原文位置和摘录 |
| 重新运行 | 预填原配置后使用创建接口和新幂等键；记录来源任务；不可用来源须先调整范围 |

T01 固定错误含义和枚举；至少区分输入非法、来源不可用、重复键冲突、容量超限、模型暂时故障、模型输出无效、处理预算耗尽、来源失效及权限撤销。映射现有 HTTP 错误风格，并保留请求标识；错误正文不得暴露模型密钥或原文。

后端 schema 是契约来源，沿用 V1 的 OpenAPI 生成约束。当前前端类型实际为手写，T01 为 V2 建立最小、可重复的类型生成入口，保留现有 HTTP 请求封装；未暴露路由的 schema 可先通过显式导出生成，不能为生成类型开放空实现接口。后续同步 `frontend/src/lib/api.ts` 与生成类型，并检查生成结果无差异；接口与对应消费者在同一切片交付，不顺带重写整个 V1 客户端。

界面任务前读 `design-system/k-platform/MASTER.md`、`pages/workspace.md`，并在首次分析界面切片补充 `pages/analysis.md`。沿用团队/知识库范围和 tokens；分析记录明确“仅本人可见”。表单保留出错输入，切换范围停止旧轮询并清除临时选择；离开不取消任务。结果表支持局部横向滚动，不能撑宽整页；以桌面、窄屏、短屏和键盘核验完成界面交付。

## 验收口径与证据

- 字段正确率：正确的已提取字段数 / 所有标为已提取的字段数；应提取内容召回率：正确提取的预期项数 / 标注中全部应提取项数，遗漏与失败均计入分母，列表按标注项计。
- 引用支持率：原文确实支持值或结论的判定数 / 全部需依据的值或结论数；无依据项计不支持。列表逐项核对。
- 未提及判断正确率：正确标记未提及的字段数 / 全部预期未提及字段数；另列错误声称未提及的次数。待核实样本另报识别情况，不通过大量使用待核实规避错误。
- 对比准确率：正确且条件完整的结论数 / 输出结论数；指定差异召回率：正确发现的标注差异数 / 指定维度内标注差异总数。输出零结论或零提取时，相应精度记为不可评估，不能算作 100% 通过。
- 指标分别报告，状态失败、超时、来源失效样本分别列明；固定输入下的系统失败不能从主样本中删去。质量目标的确认状态以 V2-SCOPE 为准。
- 真实验收记录提交、语料来源与哈希、字段定义、模型/提示词/输出 schema 版本、限制配置、结果、人工判定、耗时与用量。公开语料可保存于独立评测目录；凭据及真实用户内容不进入仓库或日志。
- 常规自动化使用确定性替身及独立测试数据库；真实模型单独执行。具体检查命令读 README 和仓库配置。复用已有 V1 回归题集及部署记录，不能把 V2 通过描述成 V1 未完成人工盲审也已通过。
